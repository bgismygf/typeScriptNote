# Interfaces 與 type

## 重點

使用哪一種屬於，個人偏好。

- Interfaces
    - 用繼承去擴充
    - 合併聲明
        - 注意: 散落不同地方，會不好維護
- type
    - 聯合類型
    - 交叉類型
---

### Interfaces

情境: 當要定義的物件，可能需要經常擴充或改變時

#### 可以用繼承去擴充

```js
interface IWidth {
  width: string;
}

interface IHeight {
  height: string;
}

interface IBoxFontSize {
  "font-size": string;
  "font-weight": string;
}

// extends 後方都是繼承的 interface
interface IBoxStyle extends IWidth, IHeight, IBoxFontSize {
  color: string;
  border: string;
  padding: string;
  margin: string;
}

const box: IBoxStyle = {...};
```

#### 名稱一樣，自動合併

注意: 如果定義相同名稱，但散落不同地方，會不好維護

```js
interface IA {
  width: string;
}

interface IA {
  height: string;
}
// 物件 box 都需要 width、height
const box: IA = {...};
```

### type

情境: 當要定義固定的資料結構

#### 可以定義 "聯合類型"

```js
type TA = number;
type TB = number | string;
```

#### 可以定義 "交叉類型"

```js
type TA = {
    name: string;
    age: number;
};

type TB = {
    id: number;
    job: string;
}

type TAB = TA & TB;
```
